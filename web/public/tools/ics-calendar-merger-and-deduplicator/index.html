How UID, RECURRENCE-ID, and SEQUENCE Deduplication Works

Combining multiple .ics exports—for example, merging archived yearly backups, consolidating overlapping team schedules, or cleaning up a calendar where an import ran twice—cannot be done by simply concatenating text files. Each file has its own VCALENDAR wrapper and VTIMEZONE blocks, and identical meetings often appear across exports at different revision stages.

Under RFC 5545 and RFC 5546 (iTIP), a calendar event's identity is defined by the tuple (UID, RECURRENCE-ID). A master recurring series has a UID and no RECURRENCE-ID, while a single rescheduled instance of that series carries the same UID plus a RECURRENCE-ID pointing to the original occurrence timestamp. When two files contain the same (UID, RECURRENCE-ID) key, this tool keeps the authoritative revision with the higher SEQUENCE integer—and if SEQUENCE ties, the most recent DTSTAMP.

When Events Still Appear Twice After Merging

If the same real-world meeting was manually created twice in two different apps (rather than invited or exported from one source), each copy will have a distinct randomly generated UID. Because RFC 5545 treats distinct UIDs as separate appointments, UID-based deduplication preserves both rather than risking accidental data loss.

Always preserve VTIMEZONE blocks when merging regional calendars: stripping a VTIMEZONE while keeping TZID=America/New_York on VEVENT entries causes strict parsers to fall back to UTC.

Frequently Asked Questions

Does merging overwrite rescheduled occurrences of a repeating meeting?
No. Moved occurrences carry a RECURRENCE-ID property, so they are keyed separately from the parent RRULE master event and preserved intact.
How large can the combined .ics file be for Google Calendar?
Google Calendar's web importer reliably accepts files up to roughly 1 MB (~1,500–3,000 typical events). For larger archives, import into Apple Calendar synced via CalDAV or split by year.
Are my uploaded .ics files sent to any server?
Never. Deduplication and file assembly happen entirely in JavaScript Blob memory inside your browser tab.
